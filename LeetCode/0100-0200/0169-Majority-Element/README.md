# [169. Majority Element](https://leetcode.com/problems/majority-element/)

## Описание задачи

Дан массив `nums` размера `n`. Верните **мажоритарный элемент** (элемент большинства).

Мажоритарный элемент — это элемент, который встречается в массиве строго больше, чем `n / 2` раз.
Вы можете быть уверены, что мажоритарный элемент всегда существует в заданном массиве.

**Строгое ограничение (Follow-up):** Можете ли вы решить задачу за время O(N) и используя только O(1) дополнительной памяти?

**Пример 1:**

- **Input:** nums = [3,2,3]
- **Output:** 3

**Пример 2:**

- **Input:** nums = [2,2,1,1,1,2,2]
- **Output:** 2

---

## Мой подход к решению

### 1. Размышления (Thought Process)

Эту задачу можно решить тремя основными путями:

**Путь 1: Хеш-таблица (Словарь) — Время O(N), Память O(N)**
Просто считаем частоту каждого числа. Как только частота превышает `n // 2`, возвращаем это число. Просто, но требует O(N) памяти.

**Путь 2: Сортировка — Время O(N log N), Память O(1)**
Если мы отсортируем массив, то число, которое занимает больше половины массива, **гарантированно** окажется в его самой середине! Нам даже не нужно ничего считать — мы просто сортируем массив и возвращаем элемент по индексу `len(nums) // 2`. Это гениальное применение свойства сортировки, но оно работает за O(N log N).

**Путь 3: Алгоритм голосования Бойера-Мура (Boyer-Moore Voting Algorithm) — Время O(N), Память O(1)**
Это самый оптимальный алгоритм. Представьте, что элементы массива — это делегаты на выборах.

- У нас есть текущий `кандидат` и счетчик его `голосов`.
- Если мы встречаем голос за нашего кандидата, счетчик растет.
- Если встречаем голос за кого-то другого — счетчик падает (делегаты нейтрализуют друг друга).
- Если счетчик падает до нуля, это значит, что все предыдущие голоса «сгорели» во взаимных спорах. Мы выбираем текущего человека новым кандидатом.
- Поскольку мажоритарный элемент составляет строго больше половины массива, его сторонники в итоге «переживут» всех остальных, и он останется последним выжившим кандидатом.

### 2. Алгоритм (Бойер-Мур)

1. Инициализировать `candidate = None` и счетчик `count = 0`.
2. Запустить цикл по каждому числу `num` в массиве:
   - Если `count == 0` (предыдущий кандидат потерял все голоса): назначить `candidate = num`.
   - Если `num == candidate`: увеличить `count` на 1.
   - Иначе: уменьшить `count` на 1.
3. Вернуть `candidate`.

---

## Анализ сложности

- **Сложность по времени (Time Complexity):** O(N), где N — длина массива. Мы проходим по массиву ровно один раз.
- **Сложность по памяти (Space Complexity):** O(1). Мы используем только две переменные (`candidate` и `count`), независимо от размера массива.
