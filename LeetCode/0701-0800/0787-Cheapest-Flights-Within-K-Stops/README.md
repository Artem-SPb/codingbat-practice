# [787. Cheapest Flights Within K Stops](https://leetcode.com/problems/cheapest-flights-within-k-stops/)

## Описание задачи

Вам дано `n` городов, соединенных рейсами. Дан массив `flights`, где `flights[i] = [from_i, to_i, price_i]` означает, что существует рейс из города `from_i` в город `to_i` со стоимостью `price_i`.

Также даны три целых числа: `src` (город отправления), `dst` (город назначения) и `k` (максимальное количество пересадок).

Необходимо вернуть **минимальную стоимость** перелета из `src` в `dst`, совершив не более `k` пересадок. Если такого маршрута не существует, верните `-1`.

**Пример 1:**

- **Input:** n = 4, flights = [[0,1,100],[1,2,100],[2,0,100],[1,3,600],[2,3,200]], src = 0, dst = 3, k = 1
- **Output:** 700
- **Пояснение:**
  Оптимальный путь с максимум 1 пересадкой: 0 -> 1 -> 3 (стоимость 100 + 600 = 700).
  Существует более дешевый путь: 0 -> 1 -> 2 -> 3 (стоимость 100 + 100 + 200 = 400), но он требует 2 пересадок, что превышает наш лимит `k = 1`.

## Мой подход к решению

### 1. Размышления (Thought Process)

- **Почему не Дейкстра?** Дейкстра по умолчанию нашел бы путь за 400, проигнорировав лимит пересадок. Чтобы адаптировать Дейкстру, пришлось бы хранить в куче не только цену и узел, но и количество шагов, что сильно усложняет логику и может привести к повторному посещению узлов (Time Limit Exceeded).
- **Алгоритм Беллмана-Форда:** Идеально подходит для ограничения по количеству ребер.
- **Суть адаптации:** Мы создаем массив `prices` размером `n`, где `prices[i]` — это минимальная цена добраться до города `i`. Изначально всё равно бесконечности, а `prices[src] = 0`.
- **Ограничение циклов:** `k` пересадок означает максимум `k + 1` перелет (ребро). Мы запускаем внешний цикл ровно `k + 1` раз.
- **Защита от "цепных реакций":** На каждом шаге цикла нам нужно обновлять цены, используя **только** цены с предыдущего шага. Если мы будем обновлять один и тот же массив `prices` на лету, мы можем за одну итерацию "проскочить" сразу несколько перелетов. Поэтому на каждой итерации мы создаем копию `tmp_prices`, записываем все улучшения туда, а в конце итерации заменяем оригинальный массив.

### 2. Алгоритм

1. Инициализировать массив `prices` размера `n` значениями `infinity`, установить `prices[src] = 0`.
2. Запустить цикл `k + 1` раз (по количеству разрешенных сегментов полета):
   - Создать копию текущих цен: `tmp_prices = prices.copy()`.
   - Пройтись по всем рейсам `[u, v, price]` в массиве `flights`:
     - Если до города `u` мы уже можем добраться (`prices[u] != infinity`):
       - Обновить цену до города `v` в копии: `tmp_prices[v] = min(tmp_prices[v], prices[u] + price)`.
   - Обновить основной массив: `prices = tmp_prices`.
3. Вернуть `prices[dst]`, если оно не равно `infinity`. Иначе вернуть `-1`.

---

## Анализ сложности

- **Сложность по времени:** $O(K \cdot E)$, где $K$ — разрешенное количество пересадок, а $E$ — количество рейсов (ребер). В худшем случае мы пройдем по всем рейсам $K+1$ раз.
- **Сложность по памяти:** $O(V)$, где $V$ — количество городов (узлов). Нам нужны только два массива `prices` и `tmp_prices` размером $V$.
