# [743. Network Delay Time](https://leetcode.com/problems/network-delay-time/)

## Описание задачи

Вам дана сеть из `n` узлов, пронумерованных от `1` до `n`. Вам также дан массив `times`, где `times[i] = [u, v, w]` означает, что сигналу требуется время `w`, чтобы дойти от узла `u` до узла `v`.

Мы посылаем сигнал из определенного узла `k`. Верните **минимальное время**, которое потребуется, чтобы все `n` узлов получили этот сигнал. Если невозможно, чтобы все `n` узлов получили сигнал (граф несвязный), верните `-1`.

**Пример 1:**

- **Input:** times = [[2,1,1],[2,3,1],[3,4,1]], n = 4, k = 2
- **Output:** 2
- **Пояснение:** Сигнал выходит из узла 2. До узлов 1 и 3 он доходит за 1 секунду. Затем из узла 3 он идет в узел 4 еще 1 секунду. Итого, последний узел получит сигнал на 2-й секунде.

**Пример 2:**

- **Input:** times = [[1,2,1]], n = 2, k = 1
- **Output:** 1

**Пример 3:**

- **Input:** times = [[1,2,1]], n = 2, k = 2
- **Output:** -1

## Мой подход к решению

### 1. Размышления (Thought Process)

- **Поиск кратчайшего пути:** Нам нужно найти кратчайшее время от стартового узла `k` до всех остальных узлов. Затем мы просто берем максимальное из этих времен (ведь сигнал распространяется параллельно, и нас интересует момент, когда он дойдет до _последнего_ узла).
- **Алгоритм Дейкстры:** Идеально подходит, так как все веса (время `w`) положительные.
- **Очередь с приоритетом (Min-Heap):** В книге Бхаргава ищет узел с наименьшим весом обычным проходом по массиву. Это дает сложность $O(V^2)$. Чтобы код летал на собеседованиях, мы будем использовать структуру "Куча" (Heap). Она умеет выдавать минимальный элемент за $O(1)$ и добавлять новые за $O(\log V)$.
- **Посещенные узлы:** Как только мы достали узел из Min-Heap, мы нашли до него гарантированно кратчайший путь! Мы добавляем его в множество `visited`. Если мы снова встретим этот узел (например, по более длинному обходному пути), мы его просто проигнорируем.

### 2. Алгоритм

1. Построить граф в виде списка смежности: `adj = {узел: [(сосед, вес), ...]}`.
2. Создать очередь с приоритетом (Min-Heap). Изначально положить туда стартовый узел: `heap = [(0, k)]` (формат кортежа: `(накопленное_время, узел)` — куча всегда сортирует по первому элементу).
3. Создать множество `visited` для отслеживания обработанных узлов.
4. Инициализировать `max_time = 0`.
5. Пока куча не пуста:
   - Извлечь узел с минимальным временем: `time, node = heapq.heappop(heap)`.
   - Если узел уже в `visited`, пропустить (continue).
   - Добавить узел в `visited`.
   - Обновить `max_time = max(max_time, time)`.
   - Для каждого соседа этого узла: вычислить новое время `new_time = time + weight`. Если сосед еще не посещен, добавить его в кучу `heapq.heappush(heap, (new_time, neighbor))`.
6. В конце проверить: если `len(visited) == n` (мы обошли все узлы), вернуть `max_time`. Иначе вернуть `-1` (какие-то узлы остались недостижимы).

## Анализ сложности

- **Сложность по времени:** $O(E \log V)$, где $E$ — количество ребер (связей), а $V$ — количество вершин (узлов). Мы можем добавить в кучу до $E$ элементов, а извлечение и вставка занимают $O(\log V)$.
- **Сложность по памяти:** $O(V + E)$ для хранения графа (списка смежности) и кучи.
