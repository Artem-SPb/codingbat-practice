# [785. Is Graph Bipartite?](https://leetcode.com/problems/is-graph-bipartite/)

## Описание задачи

Существует неориентированный граф с `n` узлами, пронумерованными от `0` до `n - 1`. Вам дан 2D массив `graph`, где `graph[u]` — это массив узлов, с которыми узел `u` имеет ребро.

Граф является **двудольным (bipartite)**, если узлы можно разделить на два независимых множества `A` и `B` так, чтобы каждое ребро в графе соединяло узел из множества `A` и узел из множества `B`. (То есть нет ни одного ребра, соединяющего два узла внутри одного множества).

Верните `true`, если граф двудольный, и `false` в противном случае.

**Пример 1:**

- **Input:** graph = [[1,2,3],[0,2],[0,1,3],[0,2]]
- **Output:** false
- **Пояснение:** Узлы 0, 1 и 2 образуют треугольник. Невозможно разделить 3 взаимосвязанных узла на 2 группы без внутренних конфликтов.

**Пример 2:**

- **Input:** graph = [[1,3],[0,2],[1,3],[0,2]]
- **Output:** true
- **Пояснение:** Мы можем разделить узлы на два множества: {0, 2} и {1, 3}.

---

## Мой подход к решению

### 1. Размышления (Thought Process)

- **Метод раскраски:** Если мы раскрасим узлы множества `A` в синий цвет, а узлы множества `B` в красный, то правило двудольного графа звучит так: _«У любого узла все его соседи должны быть противоположного цвета»_.
- **Использование BFS:** Мы берем любой стартовый узел, красим его в синий цвет (допустим, это будет цифра `1`). Затем мы смотрим на всех его соседей и красим их в красный цвет (цифра `-1`). Затем смотрим на соседей соседей и красим их снова в синий `1`. И так далее.
- **Конфликт цветов:** Если в процессе обхода мы натыкаемся на соседа, который уже раскрашен, мы просто проверяем его цвет. Если его цвет совпадает с нашим текущим — всё, правило нарушено, граф не двудольный!
- **Несвязные графы:** Граф может состоять из нескольких не связанных между собой кусков (островов). Поэтому нам недостаточно запустить BFS только от нулевого узла. Нам нужно пройтись циклом по всем узлам от `0` до `n-1`, и если узел еще не раскрашен (цвет `0`), запускать от него новый BFS.

### 2. Алгоритм

1. Создать массив `colors` размером `n`, заполненный нулями (`0` — не раскрашен, `1` — синий, `-1` — красный).
2. Запустить цикл `for i in range(n)`:
3. Если `colors[i] != 0` (узел уже раскрашен в предыдущих обходах), пропускаем его.
4. Иначе — запускаем BFS от этого узла:
   - Создаем очередь `queue` и помещаем туда `i`.
   - Красим стартовый узел: `colors[i] = 1`.
   - Пока очередь не пуста:
     - Извлекаем `node`.
     - Идем по всем его соседям `neighbor` из списка `graph[node]`:
       - Если цвет соседа совпадает с цветом текущего узла (`colors[neighbor] == colors[node]`), возвращаем `False`.
       - Если сосед не раскрашен (`colors[neighbor] == 0`), красим его в противоположный цвет (`colors[neighbor] = -colors[node]`) и добавляем в очередь.
5. Если цикл завершился и ни одного конфликта не возникло, возвращаем `True`.

---

## Анализ сложности

- **Сложность по времени (Time Complexity):** **O(V + E)**, где V — количество узлов (вершин), а E — количество ребер. В худшем случае мы посетим каждый узел ровно один раз и проверим каждое ребро.
- **Сложность по памяти (Space Complexity):** **O(V)**. Нам требуется массив `colors` размером V, а также очередь для BFS, которая в худшем случае может вмещать до V элементов.
