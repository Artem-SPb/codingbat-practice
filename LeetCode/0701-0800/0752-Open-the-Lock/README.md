# [752. Open the Lock](https://leetcode.com/problems/open-the-lock/)

## Описание задачи

У вас есть кодовый замок с 4 круглыми дисками. На каждом диске цифры от `'0'` до `'9'`. Диски можно вращать свободно: после `'9'` идет `'0'`, а перед `'0'` идет `'9'`. Каждое вращение одного диска на один шаг считается как 1 ход.

Замок изначально установлен на комбинацию `"0000"`.

Вам дан список мертвых комбинаций `deadends` (тупики). Если замок покажет любую из этих комбинаций, он заблокируется навсегда, и дальше крутить диски будет нельзя.
Также дана целевая комбинация `target`.

Найдите **минимальное количество ходов**, необходимое для открытия замка. Если открыть его невозможно, верните `-1`.

**Пример 1:**

- **Input:** deadends = ["0201","0101","0102","1212","2002"], target = "0202"
- **Output:** 6
- **Пояснение:** Возможный путь: "0000" -> "1000" -> "1100" -> "1200" -> "1201" -> "1202" -> "0202".

**Пример 2:**

- **Input:** deadends = ["8888"], target = "0009"
- **Output:** 1

**Пример 3:**

- **Input:** deadends = ["0000"], target = "8888"
- **Output:** -1

## Мой подход к решению

### 1. Размышления (Thought Process)

- **Поиск кратчайшего пути:** Как только в задаче звучит фраза «минимальное количество шагов» (shortest path) в невзвешенном графе — это 100% сигнал к использованию **Поиска в ширину (BFS)**.
- **Что такое граф в этой задаче?** Здесь нет явных узлов и ребер. Это граф "состояний". Узлами являются комбинации (от `"0000"` до `"9999"`), а ребрами — один поворот любого из 4 дисков вверх или вниз. Из каждой комбинации можно перейти ровно в 8 других состояний (4 диска \* 2 направления).
- **Мертвые концы (Deadends) и Циклы:** Чтобы BFS не зациклился (например, "0000" -> "0001" -> "0000"), нам нужно множество `visited` (посещенные узлы). Очень хитрый трюк: мы можем сразу добавить все `deadends` в множество `visited` прямо при инициализации! Таким образом, алгоритм просто никогда не пойдет в тупиковые состояния, считая, что он там "уже был".
- **Очередь (Queue):** В очереди мы будем хранить кортежи: `(текущая_комбинация, количество_сделанных_шагов)`.

### 2. Алгоритм

1. Преобразовать список `deadends` в множество `visited` (для поиска за O(1)).
2. Если `"0000"` изначально находится в `visited` — вернуть `-1` (замок сломан с самого начала).
3. Создать очередь `queue = deque([("0000", 0)])`.
4. Пока очередь не пуста:
   - Извлечь текущую комбинацию `lock` и количество шагов `turns`.
   - Если `lock == target`, вернуть `turns`.
   - Сгенерировать 8 соседних комбинаций (для каждой из 4 позиций попробовать +1 и -1):
     - Если соседней комбинации нет в `visited`:
       - Добавить её в `visited`.
       - Поместить в очередь `(соседняя_комбинация, turns + 1)`.
5. Если очередь опустела, а цель не найдена — вернуть `-1`.

## Анализ сложности

- **Сложность по времени (Time Complexity):** **O(N^2 \* A^N + D)**, где N — количество дисков (4), A — количество цифр алфавита (10), D — размер `deadends`. Всего существует $10^4 = 10000$ возможных комбинаций. В худшем случае мы посетим их все. Для каждой комбинации мы создаем строки-соседи, что занимает O(N). Итоговая сложность константна по своей природе и упирается в максимальное количество узлов: $O(10000) = O(1)$.
- **Сложность по памяти (Space Complexity):** **O(A^N + D)**. Очередь и множество `visited` в худшем случае будут содержать все $10000$ комбинаций. Это также можно считать **O(1)**.
