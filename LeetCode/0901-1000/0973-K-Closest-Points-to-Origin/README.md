# [973. K Closest Points to Origin](https://leetcode.com/problems/k-closest-points-to-origin/)

## Описание задачи

Вам дан массив точек `points`, где `points[i] = [x_i, y_i]` представляет точку на плоскости (X, Y), а также целое число `k`.

Необходимо вернуть `k` точек, которые находятся ближе всего к началу координат `(0, 0)`.
Расстояние между двумя точками на плоскости вычисляется по Евклидовой формуле: `√(x^2 + y^2)`.

Ответ можно вернуть в любом порядке.

**Пример 1:**

- **Input:** points = [[1,3],[-2,2]], k = 1
- **Output:** [[-2,2]]
- **Пояснение:** Квадрат расстояния для [1,3] равен 1^2 + 3^2 = 10.
  Квадрат расстояния для [-2,2] равен (-2)^2 + 2^2 = 8.
  8 < 10, поэтому [-2,2] ближе к началу координат.

**Пример 2:**

- **Input:** points = [[3,3],[5,-1],[-2,4]], k = 2
- **Output:** [[3,3],[-2,4]]

---

## Мой подход к решению

### 1. Размышления (Thought Process)

- **Наивный подход:** Посчитать расстояние для каждой точки, отсортировать весь массив по этому расстоянию и взять первые `k` элементов. Сложность: $O(N \log N)$.
- **Подход с Кучей (Min/Max Heap):** Можно поддерживать кучу размером `k`. Сложность: $O(N \log k)$. Но мы можем еще лучше!
- **Алгоритм Быстрого Выбора (Quick Select):** Мы только что изучили логику **Быстрой сортировки (Quick Sort)**. Там мы выбираем опорный элемент (pivot) и раскидываем массив на две части.
- Что если мы применим функцию `partition`, чтобы поставить pivot на свое финальное место? Если этот pivot оказался ровно на индексе `k`, это означает, что все элементы слева от него _меньше_ него (т.е. ближе к центру). И их ровно `k` штук! Нам даже не нужно, чтобы они были идеально отсортированы между собой, потому что задача разрешает вернуть ответ в любом порядке.
- **Главное отличие от Quick Sort:** В быстрой сортировке мы рекурсивно сортируем _обе_ половины (и левую, и правую). В Quick Select мы смотрим, где оказался наш pivot, и запускаем рекурсию **только в одной половине** (там, где находится индекс `k`). Это снижает время работы с $O(N \log N)$ до $O(N)$!

### 2. Алгоритм

1. Определить вспомогательную функцию `dist(point)`, возвращающую $x^2 + y^2$ (корень извлекать не нужно, так как $A > B \iff A^2 > B^2$).
2. Реализовать классическую функцию `partition(left, right, pivot_index)`:
   - Запомнить значение `pivot_dist`.
   - Переместить `pivot` в самый конец массива (спрятать его).
   - Пройтись по элементам: все точки с расстоянием меньше `pivot_dist` перекидывать в левую часть массива.
   - Вернуть `pivot` на его законное место между двумя группами и вернуть этот индекс.
3. Реализовать рекурсивную функцию `quick_select(left, right, k)`:
   - Выбрать случайный `pivot_index` между `left` и `right` (чтобы избежать худшего случая $O(N^2)$ для отсортированных массивов).
   - Вызвать `partition`.
   - Если итоговый индекс совпал с `k` — стоп! Мы нашли нужные элементы.
   - Если индекс меньше `k` — значит нужная нам граница находится правее. Вызываем `quick_select(index + 1, right, k)`.
   - Если индекс больше `k` — вызываем `quick_select(left, index - 1, k)`.
4. Запустить `quick_select(0, len(points) - 1, k)` и вернуть `points[:k]`.

---

## Анализ сложности

- **Сложность по времени (Time Complexity):** **O(N)** в среднем. Поскольку мы на каждом шаге отбрасываем целую половину массива и не сортируем её, сумма работы образует сходящийся ряд: $N + N/2 + N/4 + \dots \approx 2N = O(N)$. (В худшем случае, если рандом неудачный, будет $O(N^2)$, но вероятность этого при случайном pivot крайне мала).
- **Сложность по памяти (Space Complexity):** **O(\log N)** для стека вызовов рекурсии. Вся сортировка точек происходит на месте (in-place).
